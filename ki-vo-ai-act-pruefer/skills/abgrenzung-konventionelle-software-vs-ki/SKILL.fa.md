# تعریف: نرم افزار معمولی در مقابل سیستم هوش مصنوعی

## ایده اصلی

اتوماسیون یک سیگنال هشدار دهنده قوی است، اما تنها آزمایش نیست. مهم این که آیا سیستم از ورودی ها نتیجه می گیرد یا نه چگونه پیش بینی ها و محتواها را ایجاد کند، توصیه هایی برای تصمیم گیری های خودداری باید وجود داشته باشد ولی نباید بیش از حد استفاده شود: همچنین یک سیستم انسانی در حلقه ممکن است هوش مصنوعی باشد اگر تولید مبتنی بر فرضیات انجام شود.

## ماتریس مرزی

### نرم افزار معمولی

| نوع سیستم | چرا سیستم هوش مصنوعی به طور منظم وجود ندارد؟ |
|---|---|
| سوال SQL | جستجو/فلترهای ثابت، هیچ گونه انتشار مبتنی بر نتیجه گیری نیست |
| ماکرو/اسکریپت | جریان ثابت، هیچ فراینده ای از داده ها نیست |
| ماشین حساب زمان | قوانین ریاضی یا حقوقی که به طور کامل تعریف شده است |
| اعتبار دادن فرم | فیلرهای واجب یا قالب را بررسی می کند، ارزیابی نمی شود |
| داشیبورد با میانگین/مجموعه | آمار توصیفاتی بدون پیش بینی/ توصیه |
| درخت تصمیم گیری سخت کدگذاری شده | قوانین و محدودیت های کاملا انسان تعیین شده |

### موارد مرزی

| نوع سیستم | مهم |
|---|---|
| سیستم کارشناسان | فقط دانش پایه یا ارزیابی اضافی آموخته شده/بنیادگرفته؟ |
| امتیازات برتر | وزن دستی یا پارامترهای آموخته شده از داده ها؟ |
| خودکار سازی جریان کار | فقط رویت کردن با قوانین یا یک بخش هوش مصنوعی با ارزیابی؟ |
| موتور جستجو | جستجوی کامل یا رتبه بندی مبتنی بر یادگیری؟ |
| کشف کلاهبرداری | درحاله های ثابت یا مدل معادله/ طبقه بندی؟ |
| چتbot | آیا این یک سیستم مبتنی بر اسکریپت است یا یک سیستم تولید کننده و LLM؟ |
| دستیار حقوقی/رسان حقوق بشر | فقط طرح متن یا ارزیابی افراد طبیعی/تطبيق حقوق؟ |

### سیستم یا قطعه هوش مصنوعی منظم

| نوع سیستم | ویژگی های معمول هوش مصنوعی |
|---|---|
| LLM، ترانسفورماتور، چت بات تولید کننده | محتوای/ توصیه های با استفاده از اینفرنس |
| طبقه بندی کننده، Random Forest, XGBoost | الگوهای آموخته و تعیین |
| بازپسین برای پیش بینی | پیش بینی از ورودی |
| دسته بندی / گنجانده شدن | نمونه سازی یا شباهت با داده |
| تشخیص تصویری، صوتی یا عاطفی | تشخیص/ طبقه بندی مبتنی بر نتیجه گیری |
| موتور توصیه | توصیه از داده های استفاده یا زمینه |
| سیستم RAG با ارزیابی LLM | بازیافت و پاسخ تولید/فرزنگ |

## پرسش های بررسی

1. آیا از داده های تمرین، وزن مدل ها، ایمبدنها، پارامترهای آموخته یا یک مدل خارجی استفاده می شود؟
2. آیا سیستم از ورودی متغیر به طور مستقل یک خروجی تولید می کند؟
3. آیا انتشار پیش بینی، محتوا، توصیه، نمره، رتبه بندی، طبقه بندی یا تصمیم است؟
4. آیا یک انسان می تواند این نسخه را بررسی کند، قبول یا رد کند؟
5. آیا اتوماسیون فقط کنترل جریان است یا ارزیابی محتوا را انجام می دهد؟
6. آیا یک API هوش مصنوعی یا سیستم GPAI در آن قرار دارد، حتی اگر نرم افزار خود را به این ترتیب متعارف کند؟
7. آیا این سیستم در زمینه های حساس مانند اشتغال، آموزش، وام دادن و دادگستری یا مدیریت استفاده می شود؟

## اشتباهات معمول

**"در عملیات نمی آموزد، یعنی هوش مصنوعی نیست".**
اشتباه. تطبیق پس از انتشار، اختیاری است؛ یک مدل آموزش داده شده یخ زده می تواند سیستم هوش مصنوعی باشد.

**"آنها در نهایت تصمیم می گیرند، بنابراین هوش مصنوعی نیست".**
اشتباه. اشتراک گذاری انسانی ویژگی هوش مصنوعی را از بین نمی برد اگر محتوای منتشر شده بر اساس نتیجه گیری تولید شود.

**"این فقط یک API است. "**
این API می تواند یک سیستم هوش مصنوعی باشد یا بخشی از یک سیستم هوشمند. برای اپراتور، کاربرد واقعی مهم است.

"این فقط یک چت روبات است".
یک ربات عمومی مبتنی بر اسکریپت می تواند معمولی باشد. یک باتباتی مبتنی بر LLM معمولاً سیستم هوش مصنوعی است؛ اما خطر بالا فقط به هدف بستگی دارد.

**"این فقط آمار است. "**
آمار توصیفاتی اغلب از بین می رود. پیش بینی، طبقه بندی، رتبه بندی یا ارزیابی فردی به شدت برای هوش مصنوعی صحبت می کند.

## منطق نتیجه

- ** سیستم هوش مصنوعی احتمالا:** `liegt-ki-system-vor-art-3-nr-1` این گزارش ها در مورد یک نوع خطر و یا برخی از موارد دیگر نیز می باشد.
- ** نرم افزار متعارف احتمالا:** ایجاد یک اشاره منفی؛ ارزیابی مجدد در مورد بخش جدید هوش مصنوعی یا تغییر هدف.
- **مجموعه های AI را از هم جدا کنید و به طور جداگانه، بخش هایی از این فناوری را در سیستم متعارف بررسی نمایید.
- **GPAI/Chatbot تحت تاثیر قرار دارد:** `gpai-vorliegen-art-3-nr-63` و `begrenztes-risiko-art-50-transparenzpflichten`.
- **حساس بودن هدف:** علاوه بر `hochrisiko-art-6-abs-2-anhang-iii`.
